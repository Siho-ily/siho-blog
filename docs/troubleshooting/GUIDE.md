# 트러블슈팅 문서 작성 가이드

## 목적

개발 과정에서 겪은 문제와 해결 과정을 상세히 기록하여:

- 같은 문제를 다시 겪었을 때 빠르게 해결
- 학습한 내용을 체계적으로 정리
- 포트폴리오 및 기술 블로그 자료로 활용
- 미래의 나 또는 팀원에게 도움

## 작성 타이밍

✅ **즉시 작성해야 하는 경우:**

- 문제 해결에 1시간 이상 소요
- 3번 이상 다른 접근 방법을 시도
- 검색으로 쉽게 찾을 수 없는 문제
- 에러 메시지가 명확하지 않은 경우
- 라이브러리/프레임워크의 예상치 못한 동작

❌ **작성하지 않아도 되는 경우:**

- 단순 오타나 문법 오류
- 공식 문서에 명확히 나와 있는 내용
- 5분 이내에 해결된 문제

## 작성 팁

### 📝 실시간 기록하기

**문제 발생 즉시:**

```markdown
# [문제명]

## 문제 상황

- [증상 간단히 기록]
- 에러 메시지: [복사]

## 시도 기록

### 1차 시도 (진행 중)

- 생각: [이렇게 해보려고 함]
- 시작 시간: 14:30
```

**각 시도마다 즉시 업데이트:**

- 코드 붙여넣기
- 결과 기록 (성공/실패)
- 소요 시간 기록

**해결 직후:**

- 최종 코드 정리
- "왜 성공했는가?" 작성
- 전체 구조 정리

### ✍️ 글쓰기 스타일

**구체적으로:**

- ❌ "테마가 안 바뀜"
- ✅ "localStorage의 'ocean' 테마가 로드되지만 DOM에는 'coral' 클래스가 유지됨"

**맥락 포함:**

- ❌ "useEffect를 사용했다"
- ✅ "컴포넌트 본문에서 setTimeout을 호출하면 안 되므로 useEffect로 변경했다"

**코드는 완전하게:**

- ❌ 일부 생략 (`// ... 기타 코드`)
- ✅ 실제로 작성한 전체 코드 (주석 포함)

### 🎯 핵심 정보 강조

```markdown
**핵심 발견:** [가장 중요한 깨달음]

**주의사항:**

- ⚠️ [놓치기 쉬운 부분]
```

## 파일명 규칙

### 형식

```
YYYY-MM-DD-[문제-키워드].md
```

### 예시

- `2025-12-08-ssr-hydration-flicker.md`
- `2025-12-10-mdx-image-path-resolution.md`
- `2025-12-15-vercel-env-variables.md`

### 키워드 선정

- 기술 스택 포함 (ssr, mdx, vercel)
- 핵심 문제 포함 (hydration, image-path, env)
- kebab-case 사용
- 너무 길지 않게 (5단어 이내)

## 체크리스트

- [ ] 관련 파일 경로가 정확한가?
